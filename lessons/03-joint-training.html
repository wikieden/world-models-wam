讲解

第一步：训练一个样本要做的四件事（2026-11-20）

类比：教人"从模糊照片还原清晰照片"。 你拿一张清晰照片，故意糊上一层雾，让学生看糊的那张，猜"雾是从哪个方向、多浓地盖上去的"。学生猜对了方向，反着走就能把雾擦掉。

flow matching 训练一个样本：

  1. 拿真实数据 \(x_0\)（视频 latent 或动作）；
  2. 从高斯分布抽噪声 \(\epsilon\)，再随机抽一个噪声等级 \(\tau\)；
  3. 混出 \(x_\tau=(1-\tau)x_0+\tau\epsilon\)（第 2 章第二步）；
  4. 让网络 \(u_\theta\) 看 \(x_\tau\)，预测速度 \(\epsilon-x_0\)，用平方误差打分。

例子（沿用第 2 章的数）：\(x_0=0.2\)，\(\epsilon=1.0\)，\(\tau=0.3\) → \(x_\tau=0.44\)。目标速度 \(=1.0-0.2=0.8\)。网络如果猜 0.7，这一维的 loss 就是 \((0.7-0.8)^2=0.01\)。

为什么预测"速度"：推理时从纯噪声出发，沿着预测的速度反方向一步步走回去，就得到干净样本（第 4 章）。

一句话：糊一层雾，让网络猜雾的方向。

第二步：视频和动作一起进 loss（2026-11-20）

联合生成对视频 latent \(x^v\) 和动作 \(x^a\) 各自加噪（各自的 \(\tau_v\)、\(\tau_a\)），然后一个网络同时预测两者的速度：

\[ \mathcal{L}=\sum_{m\in\{v,a\}}\lambda_m\,\big\|u_\theta(x^v_{\tau},x^a_{\tau},c)_m-(\epsilon^m-x^m_0)\big\|^2 \]

逐个符号读：

  • \(m\)：modality（模态），取 \(v\)（视频）或 \(a\)（动作）；
  • \(u_\theta(\cdot)_m\)：网络输出里属于模态 \(m\) 的那一部分；
  • \(c\)：干净的上下文（历史帧、指令、本体状态）；
  • \(\lambda_m\)：读作 lambda，这一模态 loss 的权重；
  • \(\|\cdot\|^2\)：平方误差，对这一模态的所有 token、所有维度求和。

一句话：两个模态各算一份"猜雾"的误差，加权求和。

第三步：为什么动作要加权（2026-11-20）

一段样本里，视频压成 latent 后有几千个 token，动作只有几十个。loss 是对 token 求和的，所以谁的 token 多，谁就占 loss 的大头。

例子（编的整数，量级和真实接近）：视频 3000 个 token，动作 32 个，假设每个 token 的误差差不多。

设置 视频份额 动作份额 动作占比
不加权（\(\lambda_a=1\)） 3000 32 32 / 3032 ≈ 1.06%
动作 ×10（\(\lambda_a=10\)） 3000 320 320 / 3320 ≈ 9.6%

只占 1% 的话，梯度几乎全来自视频，模型会变成一个"顺便出点动作"的视频生成器。Cosmos 3 把动作 loss 乘 10，就是为了把动作拉回来（调研报告 §3 P3 第 5 条）。

一句话：动作 token 少，不加权就被视频淹没。

第四步：没有动作的视频怎么进 loss（2026-11-20）

人类视频没有动作标签。做法是：这类样本的 \(\lambda_a=0\)（或者把动作 token 遮掉），只算视频那一项。这就是第 2 章的配置 4。

一个 batch 里通常混着两种样本：

  • 机器人样本：视频 + 动作两项都算；
  • 人类 / 无动作样本：只算视频。

配比各家不同。Dyna-2 用超过 100 万小时第一人称人类视频预训练；DreamZero 在后训练时只加 20 分钟无动作视频就看到提升。

一句话：没有动作就只练视频，参数照样共享给 policy。

第五步：分块训练和时间对齐（2026-11-20）

分块 + teacher forcing（老师带着走）：DreamZero 把一段视频切成块，每块 2 个 latent 帧，一共 4 块。训练第 \(k\) 块时，前面几块用真实的干净帧当条件，只给第 \(k\) 块加噪。推理时前面的块是模型自己生成的，所以第 4 章要讲怎么补救这个"训练和推理不一致"。

时间对齐：三个频率要对上：

  • 动作控制频率：DreamZero 在 AgiBot 上是 30 Hz；
  • 一个动作块的步数：48 步，所以时长 \(48/30=1.6\) 秒；
  • 视频 latent 帧率：VAE 在时间上也有压缩，1.6 秒正好对应 2 个 latent 帧。

换一台 15 Hz 的机器人，48 步就变成 3.2 秒，和 2 个 latent 帧对不上了，块的大小要重新算（调研报告 §5 坑 4）。

还有两个坑（调研报告 §5）：

  • tokenizer（VAE）决定上限：压得太狠，手指、接触这类小细节会丢，后面怎么训都补不回来；
  • 后训练常用全量微调：DreamZero 报告 LoRA 效果不好。

一句话：前面的块用真值带着训，块长要对上整数个 latent 帧。

数学原理

  • 平方误差对 token 求和：总 loss 是所有 token 误差之和，token 数多的模态天然权重大。
  • 速度场：\(x_\tau\) 对 \(\tau\) 求导得 \(\epsilon-x_0\)，这就是网络要预测的"速度"。

公式清单

公式 意思
\(x_\tau=(1-\tau)x_0+\tau\epsilon\) 加噪
\(\frac{d x_\tau}{d\tau}=\epsilon-x_0\) 目标速度
\(\mathcal{L}=\sum_m\lambda_m\|u_\theta(\cdot)_m-(\epsilon^m-x^m_0)\|^2\) 联合 flow matching loss
动作占比 \(=\dfrac{\lambda_a N_a}{N_v+\lambda_a N_a}\) 每 token 误差相近时的近似
